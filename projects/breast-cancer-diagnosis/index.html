Breast Cancer Diagnosis Under Data Scarcity

A controlled deep-learning experiment using the Breast Cancer Wisconsin (Diagnostic) dataset to study how shrinking training data affects malignant-case recall, and whether SMOTE can recover some of the lost performance.

Problem

Medical ML experiments can look strong when plenty of training data is available. This project asks what happens when the same dataset is deliberately reduced, while keeping the held-out test set fixed.

Objective

Measure the effect of training-data scarcity on malignant recall and false negatives, then compare the same scarcity levels with and without SMOTE.

Dataset

The scikit-learn Breast Cancer Wisconsin (Diagnostic) dataset: 569 records, 30 numeric features and binary malignant/benign targets. The project uses a stratified 20% test split (114 patients), held fixed across experiments.

Preprocessing

Features are standardized with a StandardScaler fitted only on training data. Training subsets are stratified, and SMOTE is applied only to the training data after scaling.

Model architecture

A PyTorch feedforward neural network with 30 inputs, hidden layers of 64 and 32 units, ReLU activations, 0.3 dropout after each hidden layer, and a sigmoid output.

Experimental design

The training pool is reduced to 100%, 50%, 25%, 10% and 5% (455, 227, 113, 45 and 22 samples). Each condition is repeated across 10 random seeds and reported using mean and standard deviation.

RESULTS

What the experiments show

The repository results show a clear scarcity trend for the baseline model: mean malignant recall falls from 97.38% with 455 training samples to 92.62% with 22, while mean false negatives rise from 1.1 to 3.1 on the fixed 114-patient test set.

SMOTE improved mean malignant recall at every tested data size. The project documentation reports these gains as a consistent but modest trend; with 10 seeds, the individual improvements did not reach standard statistical significance.

Explainability

SHAP is used to show which patient measurements influence individual predictions and to produce a feature-level summary. The repository reports mean perimeter, mean area, mean radius and worst area among the strongest influencing features.

Uncertainty

The prototype flags predictions between 0.35 and 0.65 probability of benign as uncertain. On the recorded 114-patient test set, 7 cases were flagged. The notebook reports 98.13% accuracy on confident-only cases versus 96.49% across all cases.

Dashboard

A Streamlit interface lets a user select a test patient, view the model output and see a SHAP waterfall explanation. The current repository code expects results/final_model.pt; that saved model file is not currently present in the repository results directory, so the dashboard should be treated as a prototype requiring that artifact to run from a fresh clone.

Limitations

Results come from one benchmark dataset and one fixed test split. The uncertainty threshold was manually chosen, and the SMOTE experiment uses 10 seeds. These results should not be treated as clinical validation or as evidence of real-world diagnostic performance.

Future improvements

Use external validation cohorts, larger repeated experiments, calibrated uncertainty estimates, stronger model comparisons and a reproducible saved-model/deployment pipeline before considering any broader application.

Responsible use

This is a machine-learning research prototype, not a clinical diagnostic system. It is intended to demonstrate experimentation, evaluation and explainability—not to support real patient diagnosis or treatment decisions.

Key takeaway: The project is strongest as a data-scarcity and model-evaluation study. Its value is in asking a practical question, controlling the experiment, reporting recall and false negatives rather than accuracy alone, and being explicit about uncertainty and limitations.
