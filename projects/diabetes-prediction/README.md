# Diabetes Prediction

A refreshed, recruiter-ready implementation of my earlier academic **Diabetes Prediction** project. The original project used a Decision Tree in R on 500 training records and 268 test records. This version keeps that core idea, but reorganizes the work into a reproducible workflow with clearer preprocessing, exploratory analysis, model evaluation and a small prediction interface.

## Why this version is different

**Original academic work:** Decision Tree in R, with a fixed 500/268 split and a reported test accuracy of **79.48%**.

**Current portfolio implementation:** a clean Python workflow with an explicit preprocessing pipeline, stratified train/test split, cross-validation, a Decision Tree as the primary model, and Logistic Regression as a simple benchmark. The current implementation does **not** claim the original 79.48% was reproduced; run the project to generate fresh metrics.

## Problem statement

Use clinical measurements to classify whether a record belongs to the diabetic or non-diabetic class. This is a machine-learning demonstration project, not a medical diagnostic tool.

## Dataset

The project uses the commonly circulated Pima Indians Diabetes dataset containing **768 records, 8 input features and 1 binary outcome**. The dataset contains zero values in some clinical measurements where zero is not medically plausible; the preprocessing pipeline treats those values as missing and imputes them using training-set medians.

The repository keeps the data-download step explicit rather than silently bundling a third-party copy. Run `python download_data.py` to create `data/diabetes.csv`.

## Features

- Pregnancies
- Glucose
- BloodPressure
- SkinThickness
- Insulin
- BMI
- DiabetesPedigreeFunction
- Age

Target: `Outcome` — 0 = non-diabetic, 1 = diabetic.

## Methodology

1. Load the CSV with pandas.
2. Validate expected columns and data types.
3. Inspect class balance and basic statistics.
4. Treat medically implausible zero measurements as missing for selected features.
5. Split data using a stratified 80/20 holdout.
6. Build preprocessing and modelling steps with scikit-learn pipelines.
7. Evaluate Decision Tree and Logistic Regression using accuracy, precision, recall, F1 and ROC-AUC.
8. Use stratified cross-validation on the training set for a more stable view of model performance.
9. Save the fitted primary model for repeatable inference.

## How to run

From the project directory:

```bash
python -m venv .venv
```

Activate the environment and install dependencies:

```bash
pip install -r requirements.txt
```

Download the dataset:

```bash
python download_data.py
```

Run exploratory analysis:

```bash
python src/eda.py
```

Train and evaluate the models:

```bash
python src/train.py
```

Run a sample prediction after training:

```bash
python src/predict.py
```

## Results

The original academic report recorded **79.47761% test accuracy** for the Decision Tree on its fixed 500/268 split. The report's source code shows the original workflow using `read.csv(file.choose())`, the `tree` package, and the fixed train/test slices; its output records the 0.7947761 result.

That number is retained as the **reported/original result**. Fresh results from this refactored implementation should be generated by running the current pipeline and are intentionally not hard-coded into the README.

## Limitations

- The dataset is relatively small and is not representative of a general clinical population.
- Zero-value imputation is a practical treatment for this benchmark dataset, not a substitute for clinical measurement handling.
- Accuracy alone is not sufficient for evaluating a healthcare classifier.
- This project is for learning and portfolio demonstration and must not be used for medical decisions.

## Future improvements
